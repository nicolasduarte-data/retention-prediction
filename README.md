**Production-grade behavioral retention prediction for senior People Analytics roles.**
Reads HRIS features from [pa-warehouse](https://github.com/nicolasduarte-data/pa-warehouse) (BigQuery). v0.5 ships a dual-cohort controlled experiment (LR/GBM/EBM × HRIS-only vs hybrid) with the evaluation rigor most public HR repos skip — bootstrap-CI significance, calibration, threshold optimization, expected-value framing, nested CV, and mutation testing. Survival, fairness, and interpretability arms are on the [roadmap](#roadmap).

> **⚠ SYNTHETIC data only.** All employee records are generated by the pa-warehouse synthetic data pipeline. No real HR data is involved. This artifact is decision *support*, not decision *making* — see the **[Model Card](docs/model_card.md)**, **[Data Card](docs/data_card.md)**, and [Forbidden Uses](#forbidden-uses) before deploying.

## Results

> **Headline — and the senior-rigor signal: on this dataset, no model
> significantly outperforms another.** The six-cell comparison is reported with
> 95 % bootstrap confidence intervals, and they all overlap. Reporting that
> honestly — instead of crowning a fake winner — is the point.

**6-cell comparison — validation AUC-PR, 5,000-resample paired bootstrap:**

| Model × Cohort | AUC-PR | 95 % CI |
|---|---|---|
| **GBM × hybrid** *(champion)* | **0.309** | [0.216, 0.457] |
| LR × hybrid | 0.298 | [0.211, 0.441] |
| GBM × hris_only | 0.291 | [0.198, 0.427] |
| LR × hris_only | 0.284 | [0.201, 0.418] |
| EBM × hybrid | 0.255 | [0.184, 0.366] |
| EBM × hris_only | 0.253 | [0.183, 0.362] |

Every CI overlaps every other. The best-to-worst spread (0.056) is smaller than a
single model's CI half-width (≈ 0.12), so **no pairwise difference is significant
at n = 39 positive examples.** The bootstrap *winner-share* is the honest
tiebreak: GBM×hybrid tops 44 % of resamples (modal, not majority), LR×hybrid is a
credible alternative at 30 %. What *is* robust: the **hybrid cohort wins ~74 %** of
resamples and a **GBM-or-LR** model wins ~99 %.

### Three findings with numbers

1. **The survey signal helps directionally — but the data can't certify the
   magnitude.** Per-model survey lift `AUC-PR(hybrid) − AUC-PR(hris_only)` is
   positive for all three models (it never points the wrong way) and lifts GBM's
   **Precision@10 % from 0.25 → 0.35** — the metric HR actually feels. Yet every
   lift CI straddles zero at n = 39. Honest verdict: *the survey signal
   consistently helps and never hurts; with this sample we show the direction, not
   a certified magnitude.*
2. **The champion is a gated rank, not a leaderboard sort.** GBM×hybrid is chosen
   by a **calibration gate** — Brier ≤ the base-rate Brier `β·(1−β) ≈ 0.162` —
   *then* AUC-PR, because every downstream HR action runs on the probabilities and
   a well-ranked-but-miscalibrated model is unsafe to operate. LR and EBM fail the
   gate (balanced class weights inflate their probabilities). Held-out **test
   AUC-PR 0.274, ECE 0.048**; test calibration is marginal (Brier 0.173, just above
   the bar) and reported, not hidden.
3. **Unbiased generalisation, not the optimistic single split.** Nested 5×5 CV on
   GBM: **hybrid 0.269 ± 0.024**, hris_only 0.263 ± 0.022 — both meaningfully above
   the no-skill baseline (≈ 0.184), with the survey lift inside fold-to-fold noise,
   consistent with the bootstrap.

**The business case, in dollars.** With replacement cost ≈ 1.5 × salary and a
$2,000 retention conversation (SHRM 2024), the program breaks even once those
conversations work just **~6–7 % of the time** — the full expected-value
sensitivity sweep over intervention effectiveness is in the evaluation notebook.

- **Mutation testing** — `mutmut` on the evaluation package: 608 mutants, **0

  *ran*; mutation testing proves the tests actually *check* them.) `make mutation-test`.
- **Bootstrap-CI significance** on the comparison — error bars, not a bare leaderboard.
- **Nested 5×5 CV** for an unbiased estimate · **calibration-gated champion
  selection** · **expected-value framing** with a p_eff sensitivity sweep.
- **296 tests**, `mypy --strict`, `ruff`, `pre-commit`, CI — production scaffolding, not a notebook dump.

## Limitations

- **Single cross-section — not temporal validation.** The current mart is one
  snapshot (every row shares a `snapshot_date`), so the train/val/test split is a
  deterministic, **leak-free holdout partitioned by `employee_id`** — *not* a
  temporal split. One row per employee means no one straddles splits, so the
  estimate is honest, but it does not test month-T → month-T+1 generalisation.
  True temporal validation awaits time-series snapshots from pa-warehouse.
- **Underpowered for the R1 claim** — n = 39 positive (exit) examples. The survey
  lift is directionally positive but not statistically certifiable at this size
  (every lift CI straddles zero).
- **Synthetic data only** — model behavior on real production HRIS data is unverified.
- **Causal claims — none.** This model is Rung 1 (associational) per the
  Rubenstein 2017 / Pearl ladder framing. It ranks *who* is likely to leave; it
  does not establish what *causes* leaving, nor that intervening *causes*
  retention. SHAP + DoWhy slice is held for v1.1 only if reviewer feedback asks.
- **Single mart, single GCP project** — contract at `docs/integration_contract.md`; portability to other warehouses (Snowflake, Redshift) ships in pa-warehouse's parity tracks.

## How to Run

```bash
# Prerequisites: Python 3.11+, uv (https://docs.astral.sh/uv/), git
git clone https://github.com/nicolasduarte-data/retention-prediction.git
cd retention-prediction

# Install
uv sync

# Configure BigQuery (cross-platform)
cp .env.example .env
# Edit .env to set PA_WAREHOUSE_SA_KEY pointing at your GCP service account JSON

# Verify environment
uv run pytest                                              # 296 tests
uv run pytest --nbmake notebooks/00_environment_check.ipynb # env + BQ auth smoke
uv run pre-commit run --all-files                          # 6 hooks must pass
```

For deterministic reproducibility:
```bash
PYTHONHASHSEED=42 uv run pytest
```

See `.env.example` for the full env-var contract.

### Reproducing the MLflow experiment view

The `mlruns/` tracking store is gitignored — it's regenerated locally.
Three steps to reproduce the UI from a fresh clone:

```bash
# Step 1 — install
make install          # uv sync

# Step 2 — train (populates mlruns/ with 6 runs: LR/GBM/EBM × hris_only/hybrid)
make train

# Step 3 — open the UI
make mlflow-ui        # opens localhost:5000 — sort by auc_pr column
```

> **Note:** `make train` expects the data snapshot at `data/raw/`.
> If it's absent, the loader falls back to BigQuery (requires GCP credentials).
> Run `cp .env.example .env` and set `PA_WAREHOUSE_SA_KEY` for BigQuery auth.

See [`docs/methodology.md → MLflow Setup`](docs/methodology.md#mlflow-setup)
for the backend-store choice rationale and a full list of logged params/metrics.
